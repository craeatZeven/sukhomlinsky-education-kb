# 内容增长循环（Content Growth Loop）

> 2026-09-23 起。目的：把「按缺口补卡」变成**可重复、可交接、每批可验收**的循环。
> 缺口清单见 [coverage-gaps-by-chapter.md](coverage-gaps-by-chapter.md)（脚本 `scripts/coverage_gaps_by_chapter.py`）。

## 一、每批六步

| 步 | 动作 | 命令 / 工具 |
|---|---|---|
| 1 | **选章**：从缺口清单挑一章（优先「他本人所写 + 缺口大 + 主题重要」） | `docs/coverage-gaps-by-chapter.md` |
| 2 | **查作者归属**：读该章开头 1–2 个 unit —— 有「×××著」或第三人称评述 → **排除** | 见 §三 |
| 3 | **扫论断句**：按 `我认为/应该/必须/不能/正是/意味着` 等词过滤，只取**作者本人的论断**（叙事段不成卡） | 自写扫描脚本，规则见 §二 |
| 4 | **写规格**：把引文锚点、校勘、转述、场景写成 JSON | `templates` 见 `scripts/new_cards_from_spec.py` 头注释 |
| 5 | **产卡（先 dry-run）**：工具会拦住三类静默失败 | `new_cards_from_spec.py <spec.json>` → 人工过一眼 → `--apply` |
| 6 | **收尾**：重建索引 → 跑链 → 提交 → 推送 → **线上验收** | `rebuild_index.py` → `validate_all.py` → git → 抓 `web/data/ids.json` 与逐张卡 |

## 二、三条硬教训（已写进工具的前置校验，2026-09-23）

同一类坑一天踩了三次，现在**错在写卡之前**：

1. **锚点必须用 OCR 原文**——源里是「教育不仅是**-**门科学」（破折号当「一」），按改正后的字去找**找不到**。
   **顺序是「先按原文找到，再改」**，不是先改再找。
2. **锚点里不要放引号字符**——源常用全角 `“ ”`，锚点带 `」` 会**切片为空、内容块静默没生成**（两次）。
   要断在引号处，把锚点落在**引号外侧的词**上。
3. **unit 号跨 chunk 会重号**——`p0000-0150` 与 `p0100-0150` 是**两个不同段落**。
   → 按**正文特征**查（并要求唯一命中），或直接用源里唯一主键。

另两条（同批发现）：
- **起点标记太短会匹配到别处**（用「教学」当起点 → 切到别的位置）→ 锚点要够长且有唯一性。
- **跨 unit 的句子不能按 unit 切**（同一句常被切成两个 unit）→ 引文落在单 unit 内，或显式拼接并注明。

## 七、平行译本：同一篇文章可能在两本书里（2026-09-27 实测发现）

选集与《给教师的建议》**有重叠篇目**——同一篇文章在两处各有译本。实测：
**vol1《在实现个人全面发展思想过程中提出来的一些理论与实际问题》=《给教师的建议》(八一) 的同一篇**。

后果：若只查"本章已有卡"，会在**另一个译本**上重复产卡（内容相同、译文不同，机器查重也不易命中）。

**正确做法（选材前做）**：
1. 先按 **ref 里的小节名** 反查其他书里是否有同名/近名小节（不只 grep 本章 locator）；
2. 把平行小节里已有卡的 Excerpt **逐条读完**（不是只比标题）；
3. 命中重叠的段落**整段弃用**，改选本章其余 unit。

**实例（第六批）**：《给教师的建议》(八一) 的 6 张卡占了本章最强的 6 段 →
子代理弃用第一轮选中的 0009/0119/0077/0124，改选 0010/0111/0117/0068/0137/0146。

**给清单的启示**：缺口清单按"章节"计数时，**平行译本章节之间不是独立的缺口**；
评估"还差多少"时要扣除这层重叠（数量未知，需按篇名核对）。

## 八、平行文本不止一层：同一批内容可能出现在**三处**（2026-09-27 第二批实测）

§七 记的是"另一本书里的另一译本"。第七批又实测出**更复杂的一层**，选材前必须一起查：

| 层 | 实例 |
|---|---|
| ① 同书内不同小节 | 同一段文字在《给教师的建议》「八一」与「八四」重复出现（marker 唯一性检查拦下过） |
| ② **跨书平行译本** | vol1《在实现个人全面发展…》= 《给教师的建议》(八一) 同一篇（第六批发现） |
| ③ **跨书同源著作** | vol3《精神素养、道德和无神论》p656–671 的「基本道德素养」准则 1–5 ＝ vol4**《帕夫雷什中学》**「公民基础——道德教育的基本步骤」的同一批准则（4 张已有卡映射到 vol3 unit 0487/0461/0478 一带） |
| ④ **英译本** | `on-education`（英文）含**《公民的诞生》第 12 章整章**，即 vol3 该章的英译；候选段 0528 已被 sk-0048 占用 |

**做法（第七批实证有效）**：
1. 先按 **ref 小节名**反查平行小节（同书 + 跨书 + 英译本索引）；
2. 用**机械证据**兜底：本章每个 unit 取 3 段 16 字串全库反查；
   最终引文再做 **10 字窗口 × 全部卡片 / 12 字窗口 × 全库 units** 穷举比对（第七批结果：CARDHIT 0 / PARAHIT 0）；
3. 命中平行的段落**整段弃用**；若只是句尾踩到，**把引文截短到平行段之前**（第七批对 sk-1727/1728 就是这么处理的）。

**对"还差多少"的影响（重要）**：缺口清单按章节计数，**没有扣除这层同源重复**。
所以"剩余 ~113 章"是**上限**，实际独立内容明显更少 —— 后续若要给出可信的剩余量，
需要按"篇名/准则"而不是按"章节"去重（这是一项独立的审计工作）。

## 十、自动化只做到「规格段」为止（2026-10-01 定，用户选 A）

**起因**：仓库 `AGENTS.md` 第 20/27 行写着 —— `cards/` 是**可引用层，只有人能写、AI 只读**
（「这是出处链的端点…AI 改一个字，出处链就断了」）。而此前的自动长跑卡**直接 `--apply` 写 `cards/`**，与之冲突。

**决定（A）**：自动段**只产规格**（写 `local_working_copy/subagent-specs/`，只 dry-run），
**不写 `cards/`、不 `--apply`、不 git**；落卡由**人过目后**决定。

**同时解决了一个卡死原因**：调度器起的会话若**没绑工作区**，会落在 DSH profile 目录
（沙箱只允许写那里），一写仓库就**申请沙箱提权 → 而本部署审批提示关闭 → 请求无人应答 → 永久挂起**。
实测：#1 挂了 456 分钟、#3 挂了 45 分钟，转录最后一条都是 `approval/asked`（0 应答）；
#2 因为没把提权当必经步骤，13 分钟跑完。**修法：卡的 `workspaceId` 绑到 `D:\Work`**。

**排查看法（已固化）**：会话转录在
`D:\dsh\.dsh\sessions\<工作目录 slug>\session-<id>\session.v4.jsonl.zstd`
（zstd 压缩的 jsonl）。**挂起时看最后一条记录**：是 `approval/asked` 就是等审批，是别的再往下查。

**路径事实（2026-10-01 测）**：`D:\Git` 是 **junction → `D:\Work`**（建于 09/30 12:15）。
所以脚本里写死的 `D:\Git\...` **目前能正确解析、不是坏的**；但**新代码仍应优先从 `__file__` 推路径**
（junction 一旦被删，写死的老路径立刻失效——`prioritize_gap_chapters.py` 已按此修好）。

## 十一、A 模式的两个设计缺陷（2026-10-01 实测抓到）

规格段跑起来后，**4 批规格之间出现了 id 撞车**：

| 规格文件 | 它自己分配的 id | 问题 |
|---|---|---|
| batch-…-vol1-collectivism | sk-1749~1754 | **已被入库的卡占用**（旧卡那批落过）|
| batch-…-vol1-gongmin-jingshen-tanhua | sk-1755~1760 | 与下一批**撞车** |
| batch-…-vol2-xinnian | sk-1755~1760 | 与上一批**撞车** |
| batch-…-vol1-shaonian-jiti-huodong | sk-1761~1766 | 暂时唯一 |

**根因**：任务书让规格段「取 `cards/` 当前最大值 +1 起顺延」。但 A 模式下**规格不会被立刻入库**，
`cards/` 的最大值不变 → **每一批都算出同一段 id**。

**修法（落卡时执行，不改自动段）**：
1. **id 一律在「落卡」这一步重新分配**（`cards/` 现值 +1 起），**忽略规格里写的 id**；
2. 落卡前把该批的 section 与 `card-locators.jsonl` 比一遍，**已产卡的章整批不落**（防止规格段重复选章）；
3. 之所以第 2 条能成立：**一旦落卡，章节就进了 `card-locators.jsonl`**，自动段下次选章就会跳过它
   —— 也就是说「规格堆积不落」是唯一的危险窗口，**别让待落批次堆积**。

**教训**：把「产生」和「生效」拆成两段之后，**两段之间的状态必须有唯一的仲裁者**（这里是落卡那一步）。

## 十二、落卡标准流程（2026-10-02 用户授权「dry-run 干净就直接落」）

**授权范围**：规格段产出的规格，**若 `new_cards_from_spec.py` dry-run `exit=0` 全净 → 可直接落**，
不必逐批再问用户；**只有脏的**（dry-run 报错 / 章节查重冲突 / 内容可疑）才停下报告。

**落卡五步（每一步都不可省）**：

1. **重分配 id**：忽略规格里写的 id（规格不落库 → 每批都算出同一段 id，见 §十一）。
   取 `cards/` 里**数字 id 的最大值**（用 `^sk-(\d+)(?:-.*)?\.md$` 正则，**不要硬转 Int32**——
   有些卡名形如 `sk-0601-heros-grave`），从 +1 起顺延。
2. **逐章查重**：读规格首条的 `(book, section)`，与 `card-locators.jsonl` 精确比对；已产卡的章**整批不落**。
   （不要用关键词模糊匹配——`假期` 会误命中《做人的故事·米佳的假期》。）
3. **apply → rebuild_index → validate_all**（18 步须 ALL OK）。
4. **提交 + 推送**：只 `git add` 确实改过的路径；**绝不 `git add -A`**。`git commit -m` 里**不要带引号或反斜杠**
   （实测：`\"` 会被 PowerShell 拆成 pathspec，提交静默失败，只留下 `Everything up-to-date`——**看到这句要当失败处理**）。
5. **线上逐张验收**：等 ~110 秒，取 `web/data/ids.json` 条数 + 本批每张 `web/data/cards/sk-XXXX.json`（404 才算失败，网络抖动重试 3 次）。

**落地后归档**：把已落批次的规格文件移进 `local_working_copy/subagent-specs/_landed/`，
作废的移进 `_void/`（附 `.VOID.md` 说明）。**主目录只留待落批次**——否则将来「把目录里的都落一遍」会重落已落的。

**实测成绩（2026-10-01~02）**：规格段共产 5 批可落规格，**全部 dry-run 干净**，累计入库 **30 张**（sk-1755~1766、1767~1772、1773~1790）；
3 批作废（1 查重冲突 / 1 内容虚构 / 1 残件），**零张脏卡进过 `cards/`**。

**§十二 之补充（2026-10-02）**：落卡前**必须另查每条引文字数是否在 90~250 之间**——
工具自身只卡 `len(q) >= 12`，所以 38 字的残句也能让 dry-run 报 exit=0。
实测：`batch-2026-10-02-vol3-huihua` 的 sk-1797 只有 38 字（`造型艺术作品能在年轻的心灵中树立人的伟大感和美感，提高人在自己心目中的地位。`），
已剔除、落其余 5 张。**判据：字数 = 用 marker 定位 unit → 按 quote_from/quote_to 切片后的长度。**

**§十二 之补充二（2026-10-02，修正上一条的做法）**：字数检查**不要自己重写切片逻辑**——那会引入第二套实现，
且规格里 `quote_from` 可能不存在（实测踩过：自写审计脚本抛 `KeyError: 'quote_from'`）。

**正确做法**：字数直接从 **工具自己的 dry-run 输出**里取——每条形如
`✓ sk-XXXX pNNN｜NNN 字｜引文开头…`，正则 `｜(\d+) 字｜` 即权威长度。

判据：**任一条 <90 或 >250 → 本批不合格**（剔除该条或整批退回）。

**并且：审计步骤失败必须【阻断落卡】**。实测教训：自写审计脚本崩了，但同一条命令串里后面的 `--apply` 照跑，
结果 6 张照落（这次恰好合格，纯属运气）。→ 落卡命令要写成**审计通过才继续**（如 `if ($LASTEXITCODE -ne 0) { 报错退出 }`），
或用 Python 串起来、任一步非零就 `sys.exit`。

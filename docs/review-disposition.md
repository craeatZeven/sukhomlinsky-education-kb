## 一、修复「原文」的数据与展示契约

### 1.1 十三张「转述概括」卡（评审 A1，最严重的一条）

这 13 张卡把**编者概括**写在 `## 原文/Excerpt` 里，页面以引文样式（引号 + 引文块）呈现，
读者会当成苏霍姆林斯基的原话；而分类的「原文依据」又引用这段概括——
**概括在展示、分类、核验三处循环成为自己的依据**。

| 处置 | 张数 | 卡片 |
|---|---|---|
| 回 OCR 找到逐字原文，`原文/Excerpt` 换成真引文 | **9** | sk-0074 0075 0076 0079 0081 0125 0126 0128 0129 |
| 找不到 → 显式退回「原文待补」 | **4** | sk-0078 0083 0185 0187 |

两张都保留概括，移到新的 `## 编者概括/Summary`，一字不改。

脚本：`local_working_copy/fix_paraphrase.py`（找候选 + 逐字核验）、
`local_working_copy/fix_paraphrase_evidence.py`（换「原文依据」）。

**方法上最值得记的一点**：脚本原本想用「候选段落与概括的 4-gram 重合度」自动决定采不采，
实测这是**坏代理**——

- 概括本来就是换措辞写的摘要，所以**吻合主张的段落反而分数低**（sk-0074 只有 0.07，
  而它挑到的「期望着迈出善心的每一步都能得到表扬…反而可能长成…伪君子」恰恰就是主张）；
- 概括为空时分数虚高到 1.00（sk-0185/0187 因此挑到了**出版说明**）。

所以改成：**脚本只做可验证的事（找候选、逐字核验），采不采由人逐张看候选后拍板**
（判断表在脚本里的 `ACCEPT`，每条写明理由）。

### 1.2 指标改名（评审 A1 后半）

评审读了 `classify_llm.py` 源码，指出 `texts()` 的搜索范围是「标题 + 全部摘录 + **中文转述**」，
所以原来的「原文依据逐字对得上原文 100%」**名不副实**。已拆成两个口径：

| 口径 | 结果 |
|---|---|
| 依据能在卡片文本中找到（含转述） | 715/715（100.0%） |
| **仅凭原文摘录也成立** | **713/715（99.7%）** |
| 暂不可核验（`excerpt_status: paraphrase`，本来就无原文可比） | 3 张（sk-0078/0083/0187），显式单列 |

并注明 `evidence_match` 本就是 4 字窗口 70% 覆盖率的**模糊**匹配（为容忍 OCR 讹字），不是逐字相等。

### 1.3 展示契约（评审 A1）

`kb.js` 的目录行原来无条件给 `preview || title` 套引号 —— 编辑写的标题因此获得了原文的视觉身份。
现在：**引号只表示"这是原文"**；没有原文时改用编者概括并标「编者概括 · 原文待补」，
`build_site` 新增 `excerpt_status` 与独立的 `editor_summary`。

### 1.4 连带：验收门槛⑥ 的字面要求本身在诱人造假

`taxonomy.md` §五 门槛⑥ 原写作「无摘录为空的卡片」。这条字面要求**逼着人把概括塞进引文槽位**。
已改为「每张卡要么有逐字原文、要么显式标注『原文待补』——不允许**静默**地没有内容」，
`audit_cards.py` 与 `check_acceptance.py` 同步。**门槛没放松，是把"显式待补"与"静默空缺"分开。**

### 2.3 `problem.html` 三处确定缺陷（评审 A3·第四处）

## 四、过程中揪出的两个同类静默 bug（都值得单独记）

两次都是**同一类**：`collect` 重建 `classification.json` 时，只写它自己算得出的字段，
把**别人写进去的字段抹掉**。两次都没有任何检查会报错。

1. **facets**：677 张故事卡的**判读分面**被重算成关键词分面（关键词那版一致率只有 61.4%）。
2. **case_entries**：116 张教学案例的条目挂靠被清空，条目页的「相关案例」区**整块消失**。

都已改成从既有结果里继承。为防复发，`check_classification_shards.py` 增加了
`tax_tags` / `cases` / `case_count` 的对账断言，并接进 `validate_all.py` 末尾。

> **这一类的教训**：`collect` 是个"重建"操作，但 `classification.json` 现在承载了
> **三个不同来源**的判读产出（主归属+参见、分面、案例挂靠）。重建时必须逐字段问
> "这个字段是谁算的"——否则就是静默丢数据。

## 五、还有两处我自己的判据写错了（同样是"选错证据"）

- **顶栏折行**：我用 `scrollWidth <= clientWidth` 查溢出，而 flex 是**压窄子项让文字折行**、
  不产生溢出——判据永远为真，10 个标签全折成两行却"通过"了。该测的是**文字行数**。
- **案例区的验证脚本**：写成 `hasCase === caseSectionShown`，两者同为 `false` 时也算通过——
  **恒真式**。正是它把上面那个 `case_entries` bug 放过去了。已改成能真的失败的判据。

两次都不是"写错代码"，是**选错了证据**。

### 第 4 条值得单独记一句

「只验了默认主题」这种缺口很容易被当成形式主义——**但它这次真的藏了两个不合规**。
更值得记的是它的**成因**：最密档原来写的是 `color-mix(accent 92%, transparent)` 配**写死的白字**，
而 `--accent` 三套主题各不相同：森林是深绿（白字够），纸本是中陶色（白字 4.32，差一点），
夜读的 accent 本身是**浅**陶色（白字只有 2.75，差得远，那一档该配深色文字）。
**写死的颜色遇上按主题变的变量，只有在默认主题下才碰巧成立。**

### 另一处我自己判据的错（本轮第三次）

验证"纸卡是否居中"时我用了 `window.innerWidth` 比左右边距，结果**居中也被读出 14px 偏差**——
`innerWidth` 含 15px 滚动条，布局宽度是 `documentElement.clientWidth`。已改。
（前两次：用 `scrollWidth` 查折行、用恒真式查案例区。三次都是**选错证据**，不是写错代码。）

## 八、处置第二轮复审 §C 第 2 件：让回归证据能真的失败（2026-09-13 续）

### 8.1 先修掉我引入的三个真 bug

## 九、处置 §C 第 1 件：闭合原文身份（2026-09-13 续）

### 9.1 最后 7 张同类反例（复审读数据发现的，我上一轮漏了）

`sk-0108 / 0109 / 0110 / 0111 / 0112 / 0166 / 0167` 的摘录开头写着
「（类型为 principle，此处为精确转述，非直引）」「（类型为 method，此处为方法转述）」等——
与先前那 13 张**同类**，但**自述措辞不同**。我上一轮只按「转述概括」一个词去搜，于是漏了。
**这是我漏检的方式本身有问题：用单一措辞去搜一个语义类别。**

处置与那 13 张一致：概括移出引文槽位、放进 `## 编者概括/Summary`、卡片标
`excerpt_status: paraphrase`，卡片自述的「非直引」性质留成编者注。
**这一批不回 OCR 找原文**——卡片自己就声明是转述、没有逐字引文可核，
强行塞一段进去的风险大于收益（复审也提醒过自动挑段落的相关性不可靠）。找原文列为后续工作。

> 独立扫描 `web/data.json`：**摘录槽位里明写「转述/非直引」的卡片已清零（0 张）**，
> 这就是复审给第 1 件的停点。paraphrase 卡合计 **11 张**（第一批 4 + 本批 7）。

### 9.2 「原文待补」标记原来根本看不见

`kb.js` 把标记接在概括正文末尾，而 `.row-quote` 带 `-webkit-line-clamp: 2; overflow: hidden`，
标记落在裁切区外——**DOM 里有、肉眼看不见**。而我的验证只查了"DOM 是否包含这几个字"，
所以放过了它（本轮**第四次**选错证据）。

修法：标记独立成 `p.row-flag-line`，放在被裁剪的段落**之外**。
判据改成查**可见性**：元素有 client rects、落在行盒内、且不在 `.row-quote` 里。

### 9.3 契约统一

入门卡模板（`start-card`）原来又无条件给 `preview || title` 套引号——**同一契约在新代码里复发**。
已收进单一 `startQuote()` 函数：只有真有逐字摘录才套引号，否则用编者概括并标「原文待补」。
教训：契约要收在一个地方，散在各处手写必然复发。

/ `meta.generated=1789317517`），新增两项：

## 十一、收尾自查（2026-09-14）：修能修的，结果揪出一个线上重大缺陷

用户交办：「你先自己把能修的修一下」。修的过程里发现一个**真实、严重、且线上同样存在**的缺陷。

### 11.1 条目页与分面页**整页永久隐形**（线上同样）

| 页面 | 隐形内容 | 读者实际看到 |
|---|---|---|
| `web/entries.html` | 6 个分组 section，共 **1926 字** | 页头 + 四个统计数字 + 一大片空白 |
| `web/facets.html` | 6 个分组 section/grid，共 **863 字** | 同上 |

**根因**：`theme.js` 的滚动渐入 `reveal()` 在 `DOMContentLoaded` 里
`document.querySelectorAll("section, .grid")` **抓一次快照**就完事；而这两页的分组是
`await KB.ready()` 之后才 `innerHTML` 注入的，**永远进不了观察名单**。
CSS 当时是 `body.reveal section { opacity: 0 }` —— 对**全体** section 生效，
于是这些 section 永久停在 `opacity: 0`，**滚动也没用**。

**线上确认**：同一探针打 GitHub Pages 上的 `entries.html`，结果与本地一致
（`bodyReveal=true`、注入 6 个 section、`injectedVisible=0`、`opacity=["0"]`）。
不是本地环境问题。

**为什么 24 条判据全 PASS**：元素都在 DOM 里，几何量得到（`getBoundingClientRect`
在 opacity:0 时照样有值），颜色算得出（继承的 `color` 与透明度无关）。
**"在 DOM 里"被当成了"看得见"。** 这与本轮前面几次栽的是同一个坑，
只是这次代价最大——正是用户验收原型（「我想了解他对于劳动教育的看法，能找到吗」）
的第一步入口。

**修法（把失败模式从"内容消失"降级为"少个动画"）**：

- `reveal()` 改成"**谁被观察谁才隐藏**"：只给真的送进 `IntersectionObserver`
  的元素加 `.reveal-pending`，CSS 也从 `body.reveal section` 改为
  `body.reveal .reveal-pending`。将来任何页面漏了这步，最多是没有渐入效果。
- 再加 `MutationObserver` 接住**后加进来**的 `section/.grid`，渐入效果对异步内容照常生效。
- 18 个页面的资源缓存串从 `?v=20260907/20260909/20260913` 统一提到 `?v=20260914`
  —— 不动这个串，GitHub Pages 与浏览器会继续用旧的 `theme.js`，改了等于没改。

### 11.2 新增判据：`scan-hidden-content.mjs`（17 个页面）

对每个页面**反复滚到稳定**（先分步滚一遍，之后只要还有隐藏的 `section/.grid`
就逐个 `scrollIntoView`，最多 4 轮），只要还有 `section/.grid` 的**有效**不透明度 < 0.5
而里面有文字就 FAIL，并报出隐藏字数。
**这条判据确实能失败**：修 `theme.js` 之前跑，输出就是
`FAIL web/entries.html … 隐形块=6（1926 字）`、`FAIL web/facets.html … 6（863 字）`。

过程中三次"判据选错"，都记下来了：

1. 第一版**没滚就量** → 把 index / facets / sources 等页面"还没滚到"误报成"永久隐形"。
2. 第一版只量元素**自身** opacity → 漏掉"父级透明、子级 opacity=1"的嵌套情况，
   而且对"修复前那个 bug"反而没有分辨力（当时那些 section 连 `.reveal-pending` 都没有）。
   现已改成沿祖先链乘积。
3. 第一版只滚**一轮** → `entry.html` 的 `#caseSection` 被重建时赶不上，判据时好时坏。
   改成滚到稳定（最多 4 轮），并且**去掉了量之前的 `scrollTo(0,0)`** ——
   它会被页面里迟到的锚点滚动顶掉（实测停在 y≈680），
   把"没量到"伪装成"量过且达标"。

另外，`clusters.html` / `sources.html` 最初也报 FAIL，加第二轮 `scrollIntoView`
之后就没了——异步渲染让页面在我分步滚的过程中继续变长，被我恰好掠过。**假失败，不是 bug。**

### 11.3 目录行「三列」其实是三个挨着的 span

评审说条目页每行「名称 / 说明 / 数量」的列关系看不清。实测确认（1440px、23 行）：
`.row-link` 是 `display:flex`，于是

- 说明列的**左边缘在 108–229px 之间游走**（121px 摆幅，因为标题宽度不一）；
- 计数列多数行靠右停在 x≈553，**却被长标题的行挤到下一行的最左（x=22）**。

看起来像三列，实际是三个挨着的 span。改成 `display:grid` +
第一列定宽 `12.5rem`（最长标题「A19 道德判断与品德培养」实测 187px）后：
说明列左边缘唯一、计数列右边缘唯一；窄屏改为一列堆叠。
新增 6 条判据（两个页面 × 桌面/窄屏），并写进 `verify-hardened.mjs`（判据总数 24 → 32）。

> 判据本身也错过一次：第一版对三列都查**左**边 x，把"计数列右对齐、右边缘整齐"
> 误判成失败。**左对齐的列比左边，右对齐的列比右边。**

### 11.3b 打印会只剩首屏（同一机制的后遗症）

滚动渐入的必然推论：打印不会滚动、`IntersectionObserver` 也来不及触发，
于是打印/导出 PDF 出来的纸只有首屏那一屏内容，后面全是空白。
已在 CSS 里加 `@media print { body.reveal .reveal-pending { opacity:1; transform:none } }`，
并新增 2 条判据：用 CDP 真的切到 `print` 媒体，断言渐入元素全部显形。

### 11.4 对比度普查的两个盲点（都已堵上）

1. **只量首屏**：站点是滚动渐入的，不滚就采样等于只量了首屏，
   结论却写成"七个页面全部达标"。现在先滚到稳定再采样
   （反复滚，最多 4 轮 —— `entry.html` 的 `#caseSection` 会在案例分片载入后**被重建**，
   新元素需要新一次相交，只滚一轮会赶不上它：实测因此漏掉 7 个元素、采样数从 32 掉到 27，
   而且时好时坏）。
2. **有效性判据形同虚设**：原来读元素**自己**的 `opacity` 来决定跳过与否；
   而站点的隐藏是加在**父级 section** 上的，span 自己的 opacity 仍是 1 ——
   于是它照样去量一个读者根本看不见的行，再宣布"对比度达标"。
   现在按沿祖先链乘积的**有效**不透明度算，并把"因透明未采样"的条数与
   **是谁在透明的祖先链**一并写进结果 JSON。当前 24 处 / 21 个页面×主题组合，
   逐个查过：全是 `display:none` 的「加载更多」按钮，属正常隐藏。

> 顺带一条：量的既然是 computed style，就**不要**在量之前 `scrollTo(0, 0)`。
> 页面里迟到的锚点滚动会把它顶掉（实测停在 y≈680），于是"没量到"被伪装成"量过且达标"。
> 滚动位置与判定无关，就别动它。

### 11.5 把证据搬进版本库、把契约接进校验链

- `local_working_copy/web-audit/` 里的两份权威回归脚本 → **`tools/web-audit/`**（进 git）。
  它们在 `.gitignore` 里时，全新 clone 之后根本不存在；顺手修掉两处不可移植
  （`ROOT` 写死 `D:\Git\...`、结果 JSON 写回 gitignored 目录）。
  新增 `run-audit.ps1` 一键跑（自己起/收静态服务）与 README。

  原文槽位不许写"转述"、转述卡必须显式标注、入门卡三角色齐备、案例挂靠数现算。
  这些原来只在需要 Chrome 的脚本里，平时不会跑。
- 顺带修正：`docs/kb-status.md` 还停在改版前（写着「主题 12 个」「15 个静态页面」

### 11.6 这一节的结论

**"检查全部通过"只在判据能失败时才有意义。** 这一轮新增/修正的判据，

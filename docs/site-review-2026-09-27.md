# 站点评审（2026-09-27）

> 起因：用户说「我想先看看目前的网页」。前端（本站）此前一直在长内容（1,663 → 1,687 张卡），
> 站点呈现层没跟着评审过。本文只记**实测到的**问题与处置，不做印象式评价。
> 方法：系统 Edge + Playwright 打**线上 URL**（不是本地文件），逐页量 DOM / 资源 / 可见文本。

## 一、已修（都是"发布层丢内容/说错数"这类真缺陷）

### 1. 校勘记录在站上完全不可见 —— 影响 **296 张卡**

- **现象**：`data/cards/*.json` 里没有 `corrections` 字段；卡片页也没有对应区块。
- **根因**：`build_site.py parse_cards()` 解析「原文/Excerpt」小节时**只收 `>` 开头的行**，
  而「校勘记录（已校勘 N 处，改前→改后）」是紧跟引文的**普通行** → 被整个丢掉。
- **后果**：全库 A 政策（引文用勘正后的字 + 卡内留留痕）**只在本地可见**，对外发布层没有凭据。
- **修法**：解析器抽出 → `build_shards` 进分片 → `card.html` 单列「校勘记录」折叠块（`<details>`）→ `style.css` 加样式。
- **验收（DOM 实测）**：`sk-1600` → `{fix: true, items: 2}`（该卡正好 2 处勘正 ✓）；`sk-1687` → 2 项；`sk-1664` → 1 项。

### 2. `> 说明：…` 被当成原文显示 —— 影响 6 张卡

- **现象**：案例卡的「说明：引文为人物语言，非作者论断」被渲染成**又一段引文**。
- **根因**：它也是 `>` 行，被 excerpts 循环收进引文数组。
- **后果**：**把编者的话冒充作者的话**——这类错误在这套库里性质最重。
- **修法**：解析时 `>` 行若以「说明：」开头 → 进 `note` 字段，与引文分开渲染（`.excerpt-note`）。

### 3. 文案里的卡片数停在 1386，数据是 1675

- **现象**：`search.html`「在 1386 张卡片里检索」、`sitemap.html`「1386 张卡片详情页」、
  `taxonomy.html`（2 处）、`index.html` 的 meta description —— 站点文案与数据不一致。
- **根因**：这些数字是 202 张新卡晋升前**手写在文案里**的；晋升时没人回头改。
- **修法（根治而不是改数字）**：新增 `scripts/sync_counts.py`，只改 `web/*.html` 里
  「N 张卡片 / N 张卡」这类**文案计数**，并接进 `validate_all` 的**构建阶段**（自愈）；
  `--check` 可当闸门。另把 `search.html` 里 JS 的兜底默认值 `: 1386` 改成"数据没载入就不显示总数"。
- **验收**：线上复查 taxonomy / sitemap / explore 全为 1675，1386 归零。

### 4. 离线影子分片（`web/data/**/*.json.js`）停在旧数据

- **现象**：`index.json.js` 里 `count: 1386`。
- **处置**：重跑 `build_offline_shims.py`。**注意**：影子是生成物、在 `.gitignore` 里，
  只影响 `file://` 打开时的回退，**不影响线上**。

## 二、实测到、但**没有动**的一件事（需要方向决策）

**`explore.html` 首屏要下载 `data/index.json` = 383 KB（gzip）**，是全站最重的资源：

| 项 | 值 |
|---|---|
| `index.json` 磁盘 | 1,589 KB（1,687 行） |
| 其中唯一内容 | preview 125 KB · ref 115 KB · cn 103 KB · topics 68 KB（合计 ≈ 410 KB，与 gzip 383 KB 吻合） |
| 其余 | 字段名等**高度重复**的部分，gzip 后几乎为零 |

**为什么先不动**：这个索引有 **6 个页面**在用（explore / clusters / problem / sources / stories / search 回退），
而 `kb.js` 的列表行会显示 `preview`（引文预览）与 `cn`（中文转述）——
**砍字段就是砍列表行显示的内容**。仓库里有明确教训：为体积压掉列表内容，客观闸门全绿而**盲评输给改前**。

**三个选项**（按"不删显示内容"优先）：

| | 做法 | 首屏效果 | 代价 |
|---|---|---|---|
| **甲** | **分页取**：列表页只取当前页所需行（`index-p1.json` … 或带 range 的切片），翻页再取 | 383 KB → 约 20–30 KB | 改 `build_shards` 切分 + 各列表页取数逻辑 |
| **乙** | **瘦索引**：另出一份只含 id/标题/来源/条目/preview(≤70) 的 `index-slim.json` 给列表页 | 383 KB → 约 180 KB | 列表行的引文预览变短（**会动显示内容**） |
| **丙** | 不动，等卡片数到 3,000 再处理 | 0 | 风险后置（届时 ≈ 700 KB） |

**推荐甲**：它保住列表信息量，且一次解决（详情页早已按需分片，这是同一原则的延伸）。

## 五、第二轮：其余页面内容实查（2026-09-27，线上）

方法：Playwright 打线上 URL，读**渲染后的可见文本长度 + 卡片链接数 + DOM 节点数**，
用来区分"页面真的有内容"与"空壳页"（资源 KB 为 0 是命中缓存，不是没加载）。

| 页面 | 卡链 | DOM | 可见正文 | 判定 |
|---|---:|---:|---:|---|
| 条目页 `entry.html?code=A5` | 78 | 1925 | 12,951 字 | ✓ |
| 条目页 `entry.html?code=A11` | 86 | 2121 | 14,127 字 | ✓ |
| 分面页 `facet.html?code=S1` | 40 | 1081 | 6,049 字 | ✓ |
| `reads.html` 读本 | 0 | 500 | 2,846 字 | ✓（链到 note 页，非卡片） |
| `sources.html` 书源 | 0 | 577 | 1,781 字 | ✓（链到 explore?source=） |
| `topics.html` 专题 | 0 | 533 | 1,720 字 | ✓（链到 topic 页） |
| `coverage.html` 覆盖 | 0 | 589 | 1,306 字 | ✓ |
| `guide.html` 指南 | 0 | 312 | 829 字 | ✓ |

**结论：没有空壳页**；条目页与分面页的卡片链接数与其应有规模相符。

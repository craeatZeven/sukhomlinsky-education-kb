### 四个重点问题

**1. 三张入门卡确实有用，但选择标准不足以支撑“编者挑选”的表述。**

`build_shards.py` 实际按 quote／principle 优先，再按首段摘录最短排序。短不等于代表性强、语境完整或适合入门。

A11前两张分别讲喜爱的劳动、劳动目的，第三张突然转向“艰苦”的人道意义，而且三张都来自第五卷。第三张尤其需要上下文。保留区块，补一次有理由的编排即可，例如“为什么劳动／怎样组织／一个教学案例”，无需重做全库。

**2. 三组区别有解释，但没有做到一眼明白。**

主要论述、其他主题中谈到劳动的论述、教学案例，这个区分成立。不过正文仍采用近似的长行形式，依靠段前小字解释。

新增说明“它们本身没有中心主张”不准确：**没有分配 primary，不能推出叙事没有中心主张。** 直接称“相关教学案例与教育叙事”更可靠。

**3. 地图现在能够不记编号选关系，但主次还不清。**

中文名称已经承担选择任务。关系视图与矩阵共享数据，正常点击也能接通，功能上并非两个孤立系统。

问题是规模图、关系视图、矩阵仍全部展开并列。手机应先出现关系阅读；矩阵明确标成同一组关系的详细总览，并更新点击说明。

**4. 首页前三栏是读者说明，第四栏偏审计说明。**

不是整块都该删。第四栏缩成“分类为编辑判读，可沿链接核查依据”，把数字交给详细记录即可。

而且这四类首先是**文字与分类的身份区别**，并非四级置信度。

### 原文与数据契约：尚未闭合

- **13张特定卡的结构处理：改好了。** 当前数据确有9张替换摘录、4张独立概括及待补状态。**九张是否逐字来自对应原文：本轮看不出来。**
- **全站“引号只表示原文”：没改好。** 至少还有 **sk-0108、0109、0110、0111、0112、0166、0167**，摘录开头明确写着“转述”或“非直引”，状态却仍是 `verified`，列表继续套引号。sk-0109还在A11交叉参见中。
- **待补身份显式可见：没改好。** `kb.js` 把标记接在概括末尾，CSS又把整个段落限制为两行。S6的sk-0185实测标记位于裁切区之外。标记应移出截断容器。
- **新入门模板仍有同类风险。** 它重新无条件给 `preview || title` 套引号。当前A11三张都有摘录，不能说它们已经冒充原文；但统一契约没有贯彻到新模板。
- **门槛⑥改好了；匹配指标证明力仍被说大了。** 模糊匹配只能证明字段中文字重合，不能证明逐字一致、真实来源或分类受到语义支持。“仅凭原文摘录也成立”应改成“仅在摘录字段中达到匹配阈值”。
- **116条案例挂靠当前存在，collect继承逻辑已改；防复发验收没改好。** classification先被清空、分片随后同步清空时，两边仍然一致。需要独立判读清单或重建前后的保留约束。

### PASS 判据的问题

| 检查 | 仍可能错误通过的原因 |
|---|---|
| **案例区** | expected来自生成分片；上游与分片同时丢案例仍可能通过。分片读取失败返回−1，还可能被当成“没有案例”。行数大于零不能证明没有漏卡、错卡。 |
| **自然问句** | 实际只断言 `rows > 0`。目标预设标题只是打印，没有参与断言，返回任意无关卡也能通过。 |
| **检索总数与更多** | 只检查30行、按钮存在、文案包含“共数字张”；没有验证数字正确。点击后只要求行数增加，重复旧行也能通过。 |
| **地图** | 普通关系点击确实核了ID，这点不能抹掉；但只测顺序操作，未覆盖首次加载期间连续选择。矩阵样例主要核张数，也不足以证明卡片正确。 |
| **移动导航** | 测链接盒子的top数量，不是文字行数；“完全可见”只检查右边界，没有检查左边界及导航容器裁切。也未覆盖顶栏变高后的锚点遮挡。 |
| **入门卡** | 页面ID等于分片只证明渲染一致。`startTop < primaryTop`不证明位于首屏；双方都在屏幕下面也能过。双方同时为空也可能相等。 |
| **首页说明** | 四项数量不等于四类正确；正则找到91%、83%不等于数字可复现，更没有验证指标、样本和版本。 |
| **对比度** | 找不到某档直接跳过，不让allPass失败；没有强制核对实际主题与请求主题一致。颜色解析还用通道≤1判断是否乘255，会误读`rgb(1,1,1)`。这些漏洞不能反过来证明当前三套配色不合格。 |
| **纸卡** | 居中且宽度小于900也接受极窄纸卡；主动作class存在不等于可见。不过08截图已足够确认普通卡视觉正常，不值得继续磨像素。 |

还有**验证记录版本混用**：

`verify-review-fixes.json`实际是 **allPass:false**，保留了zzzzz命中1张的失败；后来的检索报告才通过。当前文件实测又是 **10／333**，并非记录中的 **11／335**。数字变化本身不等于检索坏了，但必须标明哪份结果对应哪个版本、替代哪段旧结果。

## B. 新问题与逐张审美

### 已确认的新问题

**1. 地图会显示“新标题＋旧关系卡片”。**

我延迟首次索引响应，先点A11→A1，再点A11→A15，随后放行：

- 标题显示“思维与智力”。
- 实际是A1的：`0282、0407、0417、0430、1073`。
- 应当显示A15的：`0270、0310、1079、1174、1176`。
- **两组都是5张。**

原因是第二次调用先改标题，再因`INDEX_LOADING`返回；第一次请求回来仍写入旧关系。需要共享加载Promise，并在渲染前确认最后选择的关系。

**2. 待补标记被行数截断。**

这是新身份展示与旧CSS组合产生的问题，不能靠“DOM包含待补文字”验收。

**3. 移动顶栏高度与跳转偏移脱节。**

390px下点击A11案例入口：顶栏底边约84.7px，标题盒顶部约77px，仍使用76px的scroll-margin，重叠约8px。两行导航保留，只需同步偏移。

**4. A18案例重叠未披露。**

“另有11条”中7条已在上方。可以交叠，但应说明“其中7条也列在上方”，不能让读者按69＋11理解库存。

**5. 新案例没有进入本条目CSV。**

源码中JSON导出包含完整entry；CSV仍只连接cards与cross。A11因此导出86条，遗漏新增16条案例。本项为源码确认，未独立下载复验。

### 逐张审美意见

1. **01-index**：第四类说明过密；三加一入口排列、醒目的统计卡仍是旧问题。不要继续增加说明区。
2. **02-entries**：仍像分类账本，先解释规则再给目录；本轮未改，不重复计为回退。
3. **03-entry-A11**：三张短中文摘录改善选择，但编选理由弱，后面仍是大引文、小中文题名的长列表。
4. **04-entry-A18**：重复案例让“又来一批”的感觉加重；没有同级条目却保留同级区标题，仍是模板残留。
5. **05-facets**：空框修好；重复徽章、状态统计和残行属于低收益细修。
6. **06-facet-S6**：竖线不能代替“编者概括”文字；两个301和长列表仍影响进入内容的效率。
7. **07-map**：中文关系入口有效，但按钮感偏弱，三个大区全部展开仍重。明确“点关系读卡片”比再改配色重要。
8. **08-card**：收窄后没有局促，纸面与正文比例合适，**可以停在这里**。
9. **09-problem**：空查询叫“匹配结果”、卡底编号串、编辑建议身份不近，都是尚存问题。
10. **10-search**：技术实现信息仍抢主视觉；不计降级横幅。
11. **11-mobile-index**：两行顶栏值得保留；标题尾部孤悬、搜索按钮像第二输入框、首页过长仍在。
12. **12-mobile-map**：保留容器横滚；关系阅读应前移，补横滑与点击提示，别再压缩矩阵数字。

## C. 按收益排序，只做三件

1. **闭合原文身份。** 处理七张明确反例，把待补标记移出截断区，让新旧模板共用身份规则。停点是已知同类反例清零、读者能实际看见标记。
2. **让回归证据能够独立失败。** 修地图换选错配、移动遮挡、案例导出；案例检查有独立依据，检索核完整ID，报告绑定版本。无需扩成庞大测试工程。
3. **做一轮有边界的阅读编排后停。** A11给编选理由，手机地图先给关系入口，A18说明交叠，首页缩短第四栏。

**现在还不是“剩下全是吹毛求疵”。** 原文身份、错关系证据都是实质问题。但纸卡宽度、阴影、边界色等已经进入收益递减。

## D. 应该停在哪一档

**三档里选第一档：“不出错”档，仍在正确性收尾。** 这不是说当前没有错误；08等局部已经有“有品”的表现，但整批尚未稳定进入第二档，更没有形成“有作者性”。

**比上一轮明显进步，但尚未整体升档。** 案例入口、关系点击、手机导航、纸卡比例的改变都有实际收益，不是在浪费力气。

阻止升档的是身份契约与验证漏洞，以及编选仍主要依赖字段、数量和摘录长度。作者性需要有理由的选择和阅读次序。完成前两项实质修正，第三项编排做一轮后就停，不必重构静态站。

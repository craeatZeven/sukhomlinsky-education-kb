# wiki/ 层的规矩（这一层的宪法）

> AI 每次在本目录动手之前先读这一页。它管的是**旁挂层**，不是卡片。
> 这一层的存在理由：卡片是「可引用层」，而你的批注、综合、问答归档需要一个地方放；
> 混在一起会让"哪句是苏霍姆林斯基、哪句是你"永远分不清。

## 一、谁写什么（划界，不可协商）

| 层 | 谁写 | 说明 |
|---|---|---|
| `cards/`（1386 张） | **只有人** | 可引用层：要对外发布、要被引用。**AI 只读**，一个字都不许改 |
| `wiki/`（本目录） | **AI 全权** | 综合、概念页、问答归档、对比页。人可以改，但默认由 AI 维护 |
| `notes/` | 只有人 | 个人批注/待办。**已 gitignore，不进公开仓库** |
| `AGENTS.md` / `taxonomy.md` / `schemas/` | 人机共演进 | 规格层 |

> **为什么不让 AI 写卡片**：Karpathy 的原话是"你几乎从不自己写 wiki——LLM 写并维护全部"。
> 这一条我们**不照做**：卡片是出处链的端点，本仓库的铁律是
> 「宁可报告找不到，也不要写一句 OCR 里没有的话」。AI 一旦能改卡片，出处链就断了。

## 二、页面类型

| 目录 | 放什么 | 命名 |
|---|---|---|
| `moc/` | Map of Content：入口页（按角度 / 条目 / 场景） | `moc/<名称>.md` |
| `concepts/` | 概念页：某个概念的跨卡综合 | `concepts/<名称>.md` |
| `queries/` | **归档的好答案**（复利燃料：问过的好问题 + 答案） | `queries/<日期>-<slug>.md` |
| `comparisons/` | 对比页（两条主张并排） | `comparisons/<名称>.md` |

**命名：本层用中文文件名。**（2026-09-14 修正，原写"一律英文 slug"）

理由：那条是照卡片的习惯定的，但两个层的**理由不同**——
卡片的文件名是英文 slug，是因为 `[[sk-XXXX]]` 必须**短且无歧义**；
本层没有这个约束，`[[宗旨]]`、`[[A11 劳动与创造]]` 读起来就是话。
（`queries/` 仍带日期前缀，便于按时间排序。）

**每条目/每角度页由脚本生成**（`web/data/meta.json` + `web/data/entry/*.json`），
不手写——手写就会出现"页面上 59 张、数据里已经变了"。

## 三、链接约定

- 引卡片：**一律 `[[sk-XXXX]]`**（id 唯一、无歧义，且可见文本最短）
- 引本层页面：`[[<slug>]]`
- **不许**用 `[[中文标题]]` 引卡片：全库有 **64 组标题重复**（同篇第二张卡），会指向不确定的那一张

## 四、每页必须有的东西

1. frontmatter：`title` / `aliases` / `type` / `updated` / `sources[]`（这一页综合了哪些卡）
2. 正文里每个实质判断后面挂**卡号**（`[[sk-XXXX]]`）——与 `topics/` 的写法一致
3. 新增或修改后，同步更新 `_log.md`（append-only）与 `index.md`

## 五、语言与边界

- 中文撰写（这个库的读者是中文使用者）
- 不整书转载；摘录保持短篇幅，遵守 `docs/copyright-policy.md`
- **不许把解读写成苏霍姆林斯基原话**：区分「他说的」与「我的综合」——这一条继承
  `AGENTS.md` 硬性规则第 5 条，在旁挂层同样生效
- 数字**从生产数据现算**，不手工抄（抄一次就有两个版本的真相）

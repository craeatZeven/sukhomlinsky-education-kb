# 定位层修复（2026-09-21）

> 站点上每张卡都写着「原文在 第X卷 · 扫描件第 N 页」。这一层是**凭据**，所以它自己的洞要单独修。

## 一、三个洞（实测）

| # | 洞 | 证据 |
|---|---|---|
| ① | **书名键不统一** | 语料存中文名（`选集（五卷本）第1卷`/`做人的故事`/`给教师的建议`），卡片与定位表用英文 slug（`xuan-ji-zh-vol1`…） |
| ② | **语言不匹配** | 4 本英文书的语料是拉丁文，旧脚本「只留汉字」的规范化把它们全滤成空串 → 「语料有页、定位没带页」 |
| ③ | **定位表里根本没有的卡** | 135 张（`ba-xin-xian-gei-hai-zi-zh` 35 · 做人的故事 31 · 选集各卷 68 · 给教师的建议 1） |

顺带查清：`ba-xin-xian-gei-hai-zi-zh`（把心献给孩子）**这本书根本不在语料里** —— 35 张卡的正文在全书规范化串里搜不到。
它们不是「定位错」，是**来源缺失**，只能如实标注。

## 二、修法：`scripts/relocate_cards.py`

- **别名归一**：`ALIASES` 把卡片 source slug 映射到语料中文书名。
- **分语言规范化**：中文书只留汉字，英文书只留字母数字（小写）。
- **多 seed 投票**：摘录里取 5 个 seed（0 / 25% / 50% / 75% / 末）逐个在全书串里找，
  得票最多且 ≥2 票 → high，1 票 → medium，0 票 → 不写并记原因。
- **坐标约定**：语料 `page` 是 **0 基**（`_ingest.py: page = 块起始 + 块内页号`），
  定位表存的是人看的 **1 基扫描件页**（2026-09-21 全局 +1 过）→ 脚本输出时 +1。

## 三、先验证再落盘：与存量定位逐条对照

拿 **1,274 条已有页码的定位**重算（不写盘），按书统计「新 − 原」：

修 +1 之后，差值**以 0 为主**：`gei-jiao-shi 22/22 · singing-feather 12/12 · to-children 21/22 · 选集各卷 55/62 · 237/281 · 144/152 · 141/147 · 177/183 · 做人的故事 381/390`
—— 合计 **1,190 / 1,274 = 93.4% 完全吻合**，其余多为 ±1~2（命中了相邻页的同一段），极少数是两次命中不同出处。

**这就是「新方法可信」的证据**：它不是另一套判据，而是与既有 v9 定位法在同一页上收敛。

## 五、还没解决的（如实记）

1. **35 张**（`ba-xin-xian-gei-hai-zi-zh`）：来源书不在语料里 → 要么补这本书的 OCR，要么在卡里写明「该书未入库，无法定位」。
2. **30 张**：正文在语料里按 5 个 seed 都找不到（多为摘录经过编辑改写、或 OCR 差异大）→ 保持「无定位」。
3. **section 粒度**：`做人的故事` 的 section 是**章级**（一章含多则小故事），所以出现「23 张同页同节」。
   页码是对的（章首页），但拿它当「同篇文章」做互链信号会误判 —— 互链清单里这类组要人工确认。

## 六、第二轮：**语料自己缺页**（2026-09-21 追加）

128 张《做人的故事》的卡，正文在语料里**逐字找得到**（5/5 seed 命中），却「定位不到」。
查下去发现根因不在定位脚本，而在**语料**：

> 《做人的故事》1,648 条 unit 里有 **126 条 `page` 为 NULL**（导入时丢的），
> 而这 128 张卡正好落在这些单元里。

**修法**：`build_index()` 里按 `unit_id` 顺序记下每个缺页单元的**邻居页**（前后最近的已知页，
且前后差值 ≤2 才采信）；命中到缺页单元时用邻居页补上，并在数据里打 `page_inferred: true`，
卡片上那行也写明「**该页为相邻单元推断**（原语料此段缺页）」。

**结论：页码有两种来路，必须分开记** ——
1. **逐字命中**（seed 命中该页，多数）
2. **相邻单元推断**（124 条；原语料缺页）

把两者混在一起写「第 N 页」，就是把推断当成了观测。

## 八、第三轮：把《把心献给孩子》补进语料（2026-09-21）

那 35 张卡（source `ba-xin-xian-gei-hai-zi-zh`）原来是**来源书不在语料里**。找来源时发现：

- 全盘只有 **中文 EPUB**：`把心献给孩子(教育思想泰斗苏霍姆林斯基的教育经典著作).epub`（孙颖译，开明出版社 2022）
- **没有带印刷页码的中文 PDF**（语料里那本 `To Children I Give My Heart` 是**英文版**）

### 做法：`scripts/ingest_epub.py`

按 EPUB 的 `text/partNNNN.html` 逐章抽取 → 每章切 400 字左右的 unit → 写进 `units` 表：

| 字段 | 值 | 为什么 |
|---|---|---|
| `page` | **NULL** | 电子版没有印刷页 —— 硬造一个「第 N 页」就是把推断当观测 |
| `section` | 章节名（学校校长 / 我的学生家长 …） | 这是这套来源能给出的上限 |
| `book` | `ba-xin-xian-gei-hai-zi-zh` | 与卡片 source 同名，别名表直接对上 |

灌入 **530 条 unit / 206,562 字**（43 章）。站点那边 `card.html` 的逻辑是「有页显示页、有节显示节」，
所以这 35 张卡现在显示「原文在 把心献给孩子 · 小节《X》（**中文电子版，无印刷页码**，故只到章节）」。

### 灌库时抓到的第二个 bug：**按书名判语言**

`locate()` 原来用调用方传进来的 `latin` 标志（由**书名**算），而 `ba-xin-xian-gei-hai-zi-zh`
是「**拉丁 slug + 中文内容**」→ 摘录被规范化成空串 → 明明有大量重叠却报「找不到」。

实测证据：修之前，sk-0009 的 14 字 seed 在 EPUB 文本里命中 **11 次**，`locate()` 却返回 None。
修法两条：① `build_index()` 改为**按内容**判语言（汉字总数 > 0 即中文书）；
② `locate()` 一律以索引里的实际语言为准，不再用调用方传的标志。

### 验证

- sk-0009 → unit `…-0043`，章节《我的学生家长》，**该 unit 文本确实含卡片引文首 24 字** ✅
- sk-0010 → 同章，含 ✅
- `validate_all` ALL OK

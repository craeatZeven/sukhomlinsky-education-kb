# 知识库分类重做规划（2026-09-10）

> 出发点：**内容最重要**。分类不是给网站做导航的架子，而是「他和这些卡片实际上在谈什么」的准确表达。
> 本规划由三份实测数据支撑，脚本在 gitignored `local_working_copy/`：`taxonomy_diagnosis.py`、`concept_census.py`、`taxonomy_v2_experiment.py`。

---

## 一、为什么必须重做（三条实测证据）

**① 现有 12 个主题不是同一层级。** 看它们各自的 summary 用的定位词就知道：

| 主题 | 自我定位（summary 原文） | 实际是哪一类 |
|---|---|---|
| 爱的教育 | 视为教育的**起点** | 态度前提 |
| 儿童研究 | 视为教育的**前提** | 认识前提 |
| 健康第一 | 放在教育的**首位** | 生理前提 |
| 家校合作 | 不可替代的**一环** | 场域 |
| 集体教育 | 成长的**土壤** | 场域 |
| 教师成长 | **核心**不是技巧 | 主体 |
| 劳动教育 | **必经之路** | 途径 |
| 阅读与书籍 | 精神生活的**起点** | 途径 |
| 思维课与大自然 | **系统课程** | 课程/方法 |
| 美育与自然 | 道德教育的**入口** | 内容领域 |
| 学习困难学生 | 帮助**某一类学生** | 对象（横切） |
| 评价与分数 | 精细的教育**工具** | 工具 |

起点 / 前提 / 首位 / 一环 / 土壤 / 核心 / 必经之路 / 系统课程 / 入口 / 对象 / 工具——十一个不同关系位。
把地基、楼层、门、钥匙、和一个需要特别照顾的房间并排当同类，是层级混装。

**② 「爱的教育」的 42% 是垃圾桶效应，不是内容多。** 库里几个高频概念**没有归属**，全部灌进它：

```
创造 189 张 → 69 张落进「爱的教育」      公民 65 张 → 40 张
幸福 122 张 → 89 张                    理想 44 张 → 31 张
精神生活 83 张 → 33 张
```

**③ 这套标签作为分区不成立。** 1386 张卡里只有 **125 张（9.0%）** 是单主题；67.7% 带两个、23.3% 带三个。面积还会重复计数（12 块相加 2710 > 1386）。

## 二、设计原则（内容优先）

1. **条目从内容量长出来**：先普查全库概念（`concept_census.py` 探了 80+ 个词），够 60 张才做一级条目，20–59 张做二级，<20 张只做标签。
2. **分层不再混装**：目的 → 前提 → 场域与主体 → 内容与方法 → 工具与评价，另设横切。
3. **每张卡有唯一主归属**（primary），多标签只作次归属——统计和地图才有干净的分母。
4. **承认这个库是两半**：论述体（718 张）和故事体（668 张）性质不同，不能硬用一套主题切（见 §四）。

## 四、故事体：不按主题切（关键判断）

**数据**：《做人的故事》541 张**全部是故事**（type=case）；全库故事体共 668 张。用品格词（诚实/勇敢/善良/勤劳/分享/感恩…）扫这 668 张，结果是**长尾**：

```
妈妈 31.0%   美 16.6%   劳动 10.8%   其余全部 <6%（诚实 1.2%、勇敢 2.2%、分享 0.7%）
```

**结论**：这些故事**每篇是一个独立情境，不是若干主题的例证**。给它们套主题，等于重复现在「爱的教育吃掉一半库」的错误。

**处理方式**：
1. **保持原书顺序通读**（`stories.html` 已按页码排序，这是对的）；
2. 另做 **10–20 组人工选集**（anthology，不是 taxonomy），按**使用场景**而非主题组织，例如：亲子共读（含"妈妈"类 207 张里选）、自然与动物、第一次羞愧、同伴之间、劳动的快乐；
3. 故事卡仍保留主题**次归属**（作筛选用），但**不参与主归属统计与地图面积**。

## 五、验证：分配实验（这是旧分类没过的那一关）

用 IDF 加权（一张卡的主归属 = 命中关键词 IDF 之和最高的条目）跑全库 1386 张：

| 指标 | 旧分类 | 新分类 |
|---|---|---|
| 能唯一归属的卡片 | 125 张（9.0%） | **1181 张（85.2%）** |
| 最大条目占比 | 41.9%（爱的教育） | **13.1%（家庭与母亲）** |
| 层级分布 | 无层级 | L0 23.0% · L1 17.3% · L2 21.9% · L3 29.4% · L4 6.9% · 横切 1.5% |

主归属分布均匀（182 / 140 / 135 / 100 / 81 / 66 / 63 / 56 / 53 / 48 / 47 / 45 / 35 / 34 / 32 / 31 / 18 / 15），**没有出现"一个条目吃掉半个库"**。

**旧主题的迁移去向**（抽样验证新体系是否接得住）：

```
阅读与书籍 94 张 → E13 37% · E15 15%      （接住了）
健康第一   61 张 → E7 48%                  （接住了）
评价与分数 48 张 → E16 44% · E8 15%        （接住了）
家校合作  326 张 → E8 39% · E3 11%         （接住了）
思维课    186 张 → E15 30% · E12 12%       （拆开了：思维归 E15，自然归 E12）
爱的教育  581 张 → E8 18% · E3 14% · E5 10% · E2 8%   （垃圾桶被分干净）
```

## 六、迁移方案

1. **卡片 frontmatter 增加两个字段**（不动现有 `topics:`，先并存）：
   ```yaml
   primary: E8            # 唯一主归属
   layers: [L2]           # 由 primary 推导，可不写
   ```
2. **旧 slug 保留为「旧标签」**，做一层兼容（筛选器可继续按旧 slug 过滤，避免 1386 张卡的外链失效）。
3. **脚本产出**：`scripts/classify_cards.py` —— 跑 IDF 规则生成 `primary` 建议值 + 一张人工复核清单（把"得分接近第二名"的卡列出来，约需抽查 100–200 张）。
4. **主题页改造**：`topics/*.md` 从 12 个扩到 18 个条目页（E1–E17 各自成页 + E18 横切页）；每页写「收录什么 / 不收录什么」的判定规则。
5. **验证并入链路**：`validate_all.py` 增加一项——每个条目的主归属数量必须落在 15–200 之间，且最大条目 ≤ 20%。

## 八、待你决策的四件事

1. **18 个条目是否要精简**？主归属 <50 的有 6 个（E17 习惯与纪律 15、E18 学习困难 18、E12 自然与思维课 31、E10 教师 32、E4 自我教育 34、E1 全面发展 35）——可以合并进相邻条目做二级，也可以保留（我倾向保留：它们都是苏霍姆林斯基的**独立主张**，不该因为卡片少就被并掉）。
2. **目的层（E1–E4）要做成第 4–7 个平行条目，还是做成一个「总纲页」**？我建议后者：目的是纲，不该和「评价与分数」平起平坐。但这会让 L0 在筛选器里消失，只在导航里出现。
3. **故事体不按主题切**——是否同意？（这是本规划里最"反直觉"的一条，但数据支持）
4. **是否接受"旧 slug 并存"**过渡期（工作量小、零破坏），还是一次性切换（干净但要改更多地方）？

定了这四件，我按 §六 的 1→5 顺序做，每步跑 `validate_all.py` 验证。

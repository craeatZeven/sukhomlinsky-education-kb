## 一、修复「原文」的数据与展示契约

### 1.1 十三张「转述概括」卡（评审 A1，最严重的一条）

这 13 张卡把**编者概括**写在 `## 原文/Excerpt` 里，页面以引文样式（引号 + 引文块）呈现，
读者会当成苏霍姆林斯基的原话；而分类的「原文依据」又引用这段概括——
**概括在展示、分类、核验三处循环成为自己的依据**。

| 处置 | 张数 | 卡片 |
|---|---|---|
| 回 OCR 找到逐字原文，`原文/Excerpt` 换成真引文 | **9** | sk-0074 0075 0076 0079 0081 0125 0126 0128 0129 |
| 找不到 → 显式退回「原文待补」 | **4** | sk-0078 0083 0185 0187 |

两张都保留概括，移到新的 `## 编者概括/Summary`，一字不改。

脚本：`local_working_copy/fix_paraphrase.py`（找候选 + 逐字核验）、
`local_working_copy/fix_paraphrase_evidence.py`（换「原文依据」）。

**方法上最值得记的一点**：脚本原本想用「候选段落与概括的 4-gram 重合度」自动决定采不采，
实测这是**坏代理**——

- 概括本来就是换措辞写的摘要，所以**吻合主张的段落反而分数低**（sk-0074 只有 0.07，
  而它挑到的「期望着迈出善心的每一步都能得到表扬…反而可能长成…伪君子」恰恰就是主张）；
- 概括为空时分数虚高到 1.00（sk-0185/0187 因此挑到了**出版说明**）。

所以改成：**脚本只做可验证的事（找候选、逐字核验），采不采由人逐张看候选后拍板**
（判断表在脚本里的 `ACCEPT`，每条写明理由）。

### 1.2 指标改名（评审 A1 后半）

评审读了 `classify_llm.py` 源码，指出 `texts()` 的搜索范围是「标题 + 全部摘录 + **中文转述**」，
所以原来的「原文依据逐字对得上原文 100%」**名不副实**。已拆成两个口径：

| 口径 | 结果 |
|---|---|
| 依据能在卡片文本中找到（含转述） | 715/715（100.0%） |
| **仅凭原文摘录也成立** | **713/715（99.7%）** |
| 暂不可核验（`excerpt_status: paraphrase`，本来就无原文可比） | 3 张（sk-0078/0083/0187），显式单列 |

并注明 `evidence_match` 本就是 4 字窗口 70% 覆盖率的**模糊**匹配（为容忍 OCR 讹字），不是逐字相等。

### 1.3 展示契约（评审 A1）

`kb.js` 的目录行原来无条件给 `preview || title` 套引号 —— 编辑写的标题因此获得了原文的视觉身份。
现在：**引号只表示"这是原文"**；没有原文时改用编者概括并标「编者概括 · 原文待补」，
`build_site` 新增 `excerpt_status` 与独立的 `editor_summary`。

### 1.4 连带：验收门槛⑥ 的字面要求本身在诱人造假

`taxonomy.md` §五 门槛⑥ 原写作「无摘录为空的卡片」。这条字面要求**逼着人把概括塞进引文槽位**。
已改为「每张卡要么有逐字原文、要么显式标注『原文待补』——不允许**静默**地没有内容」，
`audit_cards.py` 与 `check_acceptance.py` 同步。**门槛没放松，是把"显式待补"与"静默空缺"分开。**

## 二、把「我想了解 X」做成真实可走的阅读路径

### 2.1 条目页首屏分区跳转（评审 A3·第二处）

原来「交叉参见」被压在 40 行主归属 + 加载更多 + 导出按钮之后（约 6000px 深处），
页头那句「27 被参见」只是统计文字不是跳转。现在首屏有
`主要论述 59 / 相关论述·交叉参见 27 / 相关案例 16 / 同角度其他条目 / 全文里搜「劳动与创造」→`，
锚点带 `scroll-margin-top`（不被吸顶导航盖住）。

### 2.2 分出「教学案例」与「儿童故事」（评审 A3·第三处）

评审指出 `type: case` 把两种东西混成了一类。按**出处**划界（数据里就有，不靠猜）：

| 类别 | 张数 | 处理 |
|---|---|---|
| 儿童文学（《做人的故事》541 等） | 557 | 走分面（不变） |
| **教学案例 / 教育叙事**（五卷本、《给教师的建议》、On Education…） | **116** | 新判读 `case_entries`（1–3 个条目），回到主题路径 |

判读 5 个包、100% 完成。条目页因此多出「相关案例」区：
**A11 劳动与创造 +16 条、A19 +32 条**——研究某个主题的人终于看得到「这件事在教学中怎样发生」。
脚本：`scripts/case_entries.py`。

### 2.3 `problem.html` 三处确定缺陷（评审 A3·第四处）

| 原行为 | 现行为 |
|---|---|
| 整串 `includes(q)`（中文没有词边界，整句问句连预设问题都匹配不到） | 去标点与疑问词 + **distinct 2-gram 覆盖率 ≥0.6**；预设问题同一套匹配 |
| 只有浅层零结果才查全文 | **第一次查询就载入全文索引** |
| `slice(0,30)` 且把 30 当命中总数 | 总数如实显示 + 「显示更多（已显示 30 / 共 N 张）」 |

验证（`local_working_copy/web-audit/verify-problem-search.mjs`，真实渲染）：
`zzzzz` → 0 行；`孩子说谎怎么办？` → 11 张且**预设问题「孩子说谎之后怎么办」被匹配到**（正是评审点名的例子）；
`劳动` → **335** 张如实显示。

## 三、思想地图支持「选一个主题，沿关系读下去」

评审 A3·第五处：矩阵格子只是带 `title` 的 `<span>`，读者看见「A19→A4 = 14」却不能打开这 14 张。

已做：
- `map.json` 新增 `pairs`（181 条关系 × 416 个卡片 id）
- 新增**「按主题读关系」**区：下拉选条目（**完整中文名**，按 5 个角度分组），
  两栏列出「它讲到别的条目 / 别的条目讲到它」，**点任一条关系就地把那批卡片列出来**；
  默认选中 **A11**（它就是当初那个原型问题）
- **矩阵格子变成可点按钮**（有卡片时），点它会把关系视图切到行主题并列出卡片

验证（`verify-review-fixes.mjs` 的 B 节）：22 个 option、5 个 optgroup、默认 A11、
关系条目与 `map.json` 逐条相等、点关系列出的卡片数与 `pairs` 一致 —— **0 处不符**。

## 四、过程中揪出的两个同类静默 bug（都值得单独记）

两次都是**同一类**：`collect` 重建 `classification.json` 时，只写它自己算得出的字段，
把**别人写进去的字段抹掉**。两次都没有任何检查会报错。

1. **facets**：677 张故事卡的**判读分面**被重算成关键词分面（关键词那版一致率只有 61.4%）。
2. **case_entries**：116 张教学案例的条目挂靠被清空，条目页的「相关案例」区**整块消失**。

都已改成从既有结果里继承。为防复发，`check_classification_shards.py` 增加了
`tax_tags` / `cases` / `case_count` 的对账断言，并接进 `validate_all.py` 末尾。

> **这一类的教训**：`collect` 是个"重建"操作，但 `classification.json` 现在承载了
> **三个不同来源**的判读产出（主归属+参见、分面、案例挂靠）。重建时必须逐字段问
> "这个字段是谁算的"——否则就是静默丢数据。

## 五、还有两处我自己的判据写错了（同样是"选错证据"）

- **顶栏折行**：我用 `scrollWidth <= clientWidth` 查溢出，而 flex 是**压窄子项让文字折行**、
  不产生溢出——判据永远为真，10 个标签全折成两行却"通过"了。该测的是**文字行数**。
- **案例区的验证脚本**：写成 `hasCase === caseSectionShown`，两者同为 `false` 时也算通过——
  **恒真式**。正是它把上面那个 `case_entries` bug 放过去了。已改成能真的失败的判据。

两次都不是"写错代码"，是**选错了证据**。

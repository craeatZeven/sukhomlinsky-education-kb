# 苏霍姆林斯基教育知识库最终审阅意见

审阅日期：2026-09-13。

## A. 功能：能找到一部分内容，但还不能通过“带着主题问题来”的完整验收

当前最严重的问题是：**转述进入了原文槽位，路径验收没有准确测量网页可达性，教学案例又被整体排除在论述条目之外。** 这些问题比条目数量、分布是否均匀更值得先处理。

本次先完整阅读 `local_working_copy/codex-final-packet.md`，再查看第 4 节列出的全部 12 张截图，并核对相关源码、分类 JSON 和页面分片。以下区分截图观察、源码核查与数据重算；没有重跑整套 Python 验收，也没有进行独立的原著逐卡终审。10-search 的后端降级提示按本地环境产物处理；12-mobile-map 的容器内部横滚按有意设计处理。

### A1. 原文与编辑解释的边界存在已经确认的缺口

03-entry-A11 的交叉参见区里，`sk-0128`、`sk-0129` 的大字引文以“转述概括”开头；06-facet-S6 的 `sk-0076` 也如此。它们被套上引号，采用与原文摘录相同的展示方式。

这不只是字体选择。[sk-0128 的生产数据](../web/data/cards/sk-0128.json)确实把“转述概括”写在 `excerpt` / `excerpts` 字段内；其分类依据又引用了这段转述中的句子。本次扫描 [web/data.json](../web/data.json)，有 **13 张卡至少一段摘录以“转述概括：”开头**。这是一个可确定的复查范围，不能据此声称其他卡都没有问题。

[kb.js 的 cardRowHTML()](../web/kb.js)无条件给 `preview || title` 加引号，意味着编辑标题兜底时也会获得原文的视觉身份。读者即使看见“转述概括”四字，仍要自己纠正界面提供的引文暗示。

更严重的是，[classify_llm.py](../scripts/classify_llm.py) 的 `texts()`（第 54–65 行）把**标题、全部摘录、中文转述**拼在一起供依据匹配；`evidence_match()`（第 168 行起）只要求 4 字窗口覆盖率达到 70%。因此，“依据匹配通过”既不能证明依据出自原文，也不能称为“逐字核验通过”。它最多证明依据与卡片某些文字有较高重合。即使一句话确实匹配原文，也仍需判断它是否支持所选主张。

应把原文摘录、编辑转述、分类理由分别存放和标示；无法核验的摘要保留为编辑转述，不冒充原文。模糊匹配可以帮助发现 OCR 差异，但应进入复核，不能获得“逐字通过”的名称。修复后，原文暂缺的卡应如实进入待补状态，不能为维持“非空率 100%”继续填入转述。

### A2. “分类比旧标签窄 41%”目前不是有效的验收结论

材料自身已有版本冲突：第 3.2 节的劳动路径是 **142 张、旧标签差集 100 张（约 44%）**；第 5.1 节却是 **166 张、差集 92 张（约 41%）**。两者不能同时作为本轮结果。

更根本的偏差在 [path_test_prod.py](../scripts/path_test_prod.py)：

- 先用预设关键词筛出 `ids`，再只在 `ids` 中统计主归属、参见、标签和故事分面。没有命中这些词、却实际出现在条目页的卡，被计成路径到不了。
- `S12`、`S9` 等分面由脚本预先指定；脚本没有验证读者从 A11 页如何发现并走到它们。数据集合存在，不等于网页路径顺畅。
- `near` 虽配置了相邻条目，却没有用于最终 `path_set`。四题覆盖的是预设集合，并非完整用户旅程。
- “全库提到相关词”是特定词表命中的候选集，既包含误召回，也会漏掉同义表达及隐含论述，不能称为语义相关内容的“上限”。

本次直接对当前生产分片去重，得到：

| 劳动教育候选集合 | 张数 |
|---|---:|
| A11 主归属 | 59 |
| A11 交叉参见 | 27 |
| A11 页面可列出的卡片合计 | 86 |
| S12“劳动”与 S9“劳动场所”的去重并集 | 131 |
| A11 主归属、交叉参见、S12、S9 的去重并集 | **217** |

这 217 张与旧劳动标签的 225 张比较：旧集合有 **63 张**不在该并集中，新并集有 **55 张**不在旧集合中。依据是 [A11](../web/data/entry/A11.json)、[S12](../web/data/facet/S12.json)、[S9](../web/data/facet/S9.json) 及 [classification.json](../classification.json)。

**217 不是修正后的“相关性正确答案”，63/225 也不是实际漏召回率。** 它们只说明材料中的 142/166 不是这几个页面的完整库存。217 张仍需审相关性，路径仍需验证可发现性；63 张也可能同时包含旧标签误收与新结构漏收。

因此，对“变窄是否可接受”的回答是：**数量变少本身不算缺陷；未经相关性复核便宣布损失合理，才是验收缺口。** 应从差集里抽取卡片，分别标记“真正相关但漏入口”“仅背景提及”“旧标签误收”“有入口但难发现”，再判断精度收益是否抵偿损失。全文检索保留是必要条件，但不能替代这项评估。

### A3. 真正会断在什么地方

**第一处：读者必须先理解多套入口的关系。** 首页同时出现 12 个主题、23 个条目、故事分面、541 篇故事、“主题浏览”和“教育专题”。这些可以共存，但需要用读者任务说明差异，例如“12 篇编辑导读”“按概念找卡片”“按故事情境找素材”“按《做人的故事》原书顺序读”。目前“12 主题”和“23 条目”容易被理解成尚未统一的分类版本；“API 检索”也没有告诉普通读者这是全库搜索入口。

**第二处：A11 的参见被压在长列表之后。** 03-entry-A11 中，首批 40 行主归属、加载按钮和导出按钮之后才出现交叉参见，约在六千像素深处。页头“27 被参见”只是统计文本，不是跳转。“参见区存在”不等于读者看得到参见。首屏应有“主要论述 59 / 相关论述 27 / 相关案例与故事”这样的明确跳转。

**第三处：论述与故事分流混淆了卡片类型和作品体裁。** 材料说 673 张故事“是给孩子读的短故事，谈处境而非主张”；但 [sk-0068](../web/data/cards/sk-0068.json) 是《给教师的建议》中的教育案例，06-facet-S6 还列有学校体育实践、107 名学习困难学生的教育案例。它们不能因 `type: case` 就被统一当成儿童文学故事。

研究劳动教育的人通常也需要“这项主张在教学中怎样发生”。把实践证据从论述入口移走，会割断观点与案例之间的关系。建议保留儿童文学的角色／场景分面，同时区分“教学案例”和“儿童故事”；教学案例可以作为某条论述的例证进入主题路径，不必硬把所有叙事改判成原则卡。即使暂不改类型，先做明确的案例关联，也比页底只给故事分面总入口有效。

**第四处：“问题检索”不能稳定承担全文检索兜底。** [problem.html](../web/problem.html) 源码存在以下确定行为：

- 查询用整段字符串 `includes(q)`，没有从自然问句提取关键词。页面示例“孩子说谎怎么办？”并不是预设标题“孩子说谎之后怎么办”的连续子串；正常问句可能连对应预设问题都匹配不到。
- 浅层标题／转述／预览只要有一条命中，就不会进一步合并完整原文匹配。宣称搜索全部原文，实际却可能漏掉仅在完整摘录中出现的结果。
- 匹配先 `slice(0,30)`，再用截断后的长度显示“卡片命中”；没有分页或“查看全部”的出口。超过 30 条时，展示数量会被误读成总量。

这是源码核查结论，不是根据 09 的空查询截图推测，也与 10 的 Worker 降级横幅无关。应让问题页负责常见问法与编辑导读，把真实全库结果交给同一套搜索逻辑；展示总数、已显示数及更多结果入口。

**第五处：地图不能沿一条关系读证据。** [clusters.html](../web/clusters.html) 中，行列标题能进入条目页，但矩阵单元格只是带 `title` 的 `span`，只绑定鼠标移入／移出高亮。读者看见 A19→A4 的 14 张，不能就地打开这 14 张；进入 A19 后仍要自己筛。这是地图作为内容入口最明显的断点。

### A4. 对材料自列 11 条弱点的逐项判断

| 第 5 节项目 | 判断 |
|---|---|
| 1. 分类路径变窄 | 数量收窄不自动构成缺陷；现有差集口径有误，尚不能证明损失合理，见 A2。 |
| 2. 判读概率性 | 风险成立，但 82.8%／91.1% 是相对独立判读的一致率，不能直接说“全库每六张／十一张有一张错”。应披露样本、判读身份、分歧与复核方式，而非给每张卡套一个总体错误概率。 |
| 3. 5 张无分面 | 是分类入口的真实遗漏，但不等于全站无法访问。99.3% 满足覆盖率 ≥95% 的门槛⑤，却不满足“每张故事至少一个分面”的门槛①；应有“待归类”入口或显式例外，不能两项都判通过。 |
| 4. 分面 83% | 不能仅凭低于 91% 判为退步。多选分面与单选角度须先统一指标，说明是完全匹配率、逐标签精度／召回还是其他口径；“边界软”也不能代替分歧分析。 |
| 5. 只投喂首段 | 是应补完的明确工作。38 张已可定位，不能用全库字数占比替它们担保；应读全段复判，并检查主归属、参见与依据是否变化。 |
| 6. 统计图不是地图 | 不要求强行画地理意象；矩阵作为详细视图合理。但“完整网络密集”只能反对同时展开全部边，不能证明分组导航、单主题邻域或渐进展开不可做。用户想要的空间导航体验仍未充分兑现。 |
| 7. 顶栏横滚 | 桌面略窄时可以接受；390px 下品牌与主题按钮挤得导航几乎只剩“首页”和下一项残片，是可发现性问题。它与 12 中合理的矩阵局部横滚不是同一种取舍。 |
| 8. 未回写 frontmatter | **不回写本身不算缺陷**：分类 JSON 可以是良好设计，仓库也并非“没有分类信息”。问题是 Markdown 单文件消费者拿不到新分类，需要稳定 ID 关联说明、版本信息和合并导出，并标清旧 topics 的性质。 |
| 9. 过程文档多、置信层级弱 | 过程文档多不是问题，读者不必读审计史。08 已有“中文转述”“不是原文”的说明，07 也写了“编辑主归属分布”，所以不能说全站完全没有披露；但 A1 的混用未因此解决。 |
| 10. 矩阵对比度 | 另两套主题未实测是验收缺口，不能据默认截图宣布它们不合格或已达标。当前更直观的障碍是编号轴标签、悬停依赖和无法点开关系卡片，不只是深浅颜色。 |
| 11. 错误判据放过缺陷 | 已修的条形高度、导航折行不再记作当前缺陷。后续应核对真实可见高度、文字行数、视口裁切和可操作结果；不需要因此引入框架。 |

另有两条论证需要收回过度结论：

- **“多词条被数据证伪”不成立。** 52 张探针没给两个参见，不等于不需要多个主题入口；65% 给了一个参见，已经说明大量卡片涉及至少两个条目。416 条参见分布于 399 张卡，也说明全量存在多于一个参见的卡。保留“一个主归属＋多个参见”可以是合理设计，但它是保留主次关系的选择，不是对多值主题检索的证伪。A6 入边数大于主归属数，也不能单独证明它总是“前提”；确认这种关系语义还得读具体卡片。
- **抽样一致率不等于真值上限。** 审计文档本身已说明共同偏差不会被一致率捕获；材料却又写成“判读彼此一致（人，噪声地板）”。现有说明不足以核实判读者确为人工专家，应明确身份与独立性。159/192 是已有判读样本的对照，也不能未经说明当作当前全部生产分类的最终正确率。

## B. 审美：逐张意见

整体最大的拖累是**内容选择界面仍按数据库字段来讲话**：编号、归属、计数、分面状态占了很多空间，帮助读者判断“先读什么”的中文标题和解释却常缩进小字。纸色、深绿和衬线字有一致性，但不足以抵消这个问题。

按“不出错／有品／有作者性”三档划分：**整批交付仍在“不出错”档打磨，若干阅读区域已接近“有品”，尚未形成稳定的“有作者性”。** 空框、错误的引文身份、手机导航残片和地图读数障碍仍然可见。作者性应来自明确的编选与阅读路线，不是再添纹理、英文眉题或装饰。

“档案层／阅读层分而治之”部分做到了：顶底栏有深色框架，详情有浅色纸面，列表与详情形状也有区分。但列表、分面等档案内容仍主要铺在浅色背景上，不宜宣称已严格做到“列表走深色 chrome”。这本身不必判失败；为兑现字面方案把所有列表染深，并不会解决下面的问题。

### 01-index

- **副标题重复“从原著里长出的教育智慧”**，又塞入 Agent 检索，首屏更像项目介绍而非读书入口。保留一句面向读者的说明即可。
- **四张入口卡排成三加一**，孤立的“按故事读”形成不必要的空档；四项同级入口采用两列或四列会更均衡。
- **带阴影的四块数量卡过于醒目**；“12 主题”与新分类口径存在理解冲突。保留数量，降低装饰权重，写清“12 篇专题导读”等实际含义。
- 彩色 emoji 与其余页面克制的书刊气质不协调。“看结构”中的“十组教育主张”仍是旧描述，与 07 的五角度、22 个持卡条目不一致，应同步改文案。

### 02-entries

- **第一组条目前，先经过标题、规格介绍、四块统计和读表说明**。读者先学分类法才能读内容，首屏过重；折叠详细规则，优先露出五组目录。
- 名称、收录解释挤在同一行，右端又有两项计数；名称与说明没有固定列关系，长短条目扫读不整齐。应稳定“名称／简短范围／数量”三层。
- A7、A17 解释中的“原在某角度、评审后移入”等过程文案干扰阅读。迁移史放进文档。
- “二十三条目”并非不可用，但应醒目说明“22 个论述条目＋1 个跨条目标记”，避免 A18 被理解成同类的第二十三格。

### 03-entry-A11

- **大号引文占据每行主视觉，中文题名却缩在元数据里**。中英文摘录交替时，中文读者难快速判断内容。建议中文题名优先，下面放短预览与身份标记，类型和编号退到次级。
- 页头“收录口径”在“主归属”说明里再说一遍，浪费首屏。
- **交叉参见埋得过深**，两区又采用几乎相同的长行样式。首屏应有锚点和持续可见的分区位置提示，不能只换参见标题的颜色。
- “转述概括”和“（类型为 method，此处为方法转述）”直接进入引文主视觉，是内容与呈现共同造成的拖累，优先级高于行距微调。

### 04-entry-A18

- 页头、统计旁、正文反复解释“不参与主归属分区”，**实现说明压过了学习困难学生这个主题**。一句“跨条目汇集，69 张相关卡片”足够承担入口说明。
- 连续几行长英文预览，中文题名仍很小，降低中文知识库的浏览效率。
- **页尾先立“同一角度下的其他条目”标题，再解释没有同级条目**，是明显模板残留。应移除整个空用途区块。
- A18 独立可点不算缺陷；拖后腿的是反复解释它为什么特殊，却没有帮助读者继续缩小 69 张卡的范围。

### 05-facets

- **统计区下方有一条空的浅绿描边框**，像尚未填好的提示栏。源码的 #pending 在 ready 状态没有隐藏，属于确定的显示残留。
- “3 字段／17 分面／673 卡／2242 标记／已就绪”把内部数据状态做成主角。“已就绪”不帮助选择故事，标记总数也应降级。
- 小卡重复角色／场景／事件或情绪徽章，分组标题已经说明；重复徽章比名称更零碎。
- 五、五、七项分别排三列，连续出现残行；不是溢出错误，但页面节奏松散。更紧凑的分类清单或随组调整的网格会更像目录。

### 06-facet-S6

- **“场景”统计卡和两个相同的 301 统计卡重复传递信息**，占掉进入故事前的大块空间。保留“自然与季节 · 301 张”即可。
- 301 张材料靠长摘录纵向扫读，缺少分面内搜索、角色／事件的组合缩小入口。“加载更多”能继续看，不等于能找到想要的那篇。
- 行元数据重复“故事体 · 走故事分面”，但读者已在分面内；可以改成这张卡实际涉及的角色或事件。
- 体育实践、教学案例与后面儿童故事的语体差别很大，会被感受到为编选不稳。根因见 A3，不能仅靠统一字号修好。

### 07-map

- **轴标签只剩 1、2、3、4、19、5……**，读者必须记住编号与名称的对应关系。上方完整名称的条形区与矩阵相距很远；角度色带不足以消除查表负担。至少提供固定行名称和当前列名称，或常驻的选中关系解释区。
- **22×22 网格占据巨大面积，默认状态没有替读者选出第一条可读关系。** 默认画面可采用“选择一个主题 → 看它与其他主题的联系”；完整矩阵留作“查看全部关系”。
- 原始计数受条目库存影响，“14 张”比“4 张”深，不一定代表思想关系更强。保留计数，将“方向与强度”改为“参见方向与张数”；如需比较比例，再提供明确分母，并避免夸大小样本。
- **A18 的 69 张被画成 100% 宽灰条**。虽另列复分标签，仍沿用数量图的视觉语法，长度却没有与上方 86 张等值缩放。建议改成独立文字入口，或明确采用相同刻度。
- “少／中／多”没有数值范围；源码当前阈值对应 1–3、4–8、9–14，应让图例讲清楚。空白零值与对角线也应明确区分。
- 底部“为什么不是网络图”偏向为实现辩护；换成具体读图例子更有帮助。还须分清 **416 次卡片参见、181 个非零有向关系格、123 对相连条目**；按 416 算出的 37.8 是加权连接次数，不是每个条目有 37.8 个不同邻居。
- **不强制改成全量节点连线图。** 矩阵可以保留为详细视图。不够“地图”的原因是缺少主题定位、局部探索和沿关系进入原文的动作，并非没有山川河流。

### 08-card

- **正文窄，外层纸卡却很宽，文字贴左，右边留下大片空白**。保留适宜行长，把正文列居中或缩窄纸卡，不必为填满而拉长引文行。
- 顶部 A5 徽章与“这一条属于”重复；“还涉及哪些条目 —”是无内容字段。减少重复和空值展示，给出处与原文让位。
- **A18 只显示编号**，没有“学习困难学生”名称，普通读者无法识别这个入口。
- 出版信息、核验说明和操作按钮都很小。不是所有元数据都要放大，但“来源／定位”“中文转述”应明显到能被看见。此页已区分中文转述，不能批评为完全没有来源意识。
- 复制引用、分享、打印、同来源、INDEX 五个按钮近乎同权；阅读常用动作优先，仓库定位等放到次级。

### 09-problem

- **查询框为空却叫“匹配结果”**，下面其实是 16 个预设问题。空状态应叫“常见问题”，输入后才显示匹配结果。
- 每卡末尾是极小的 sk-XXXX 链接串，点击前不知道各卡内容。给出“先读这张”的中文标题，余下关联卡收进明确入口。
- 问题摘要使用行动建议语气，近旁却没有“编辑者应用建议”标识；结合页头“找到苏霍姆林斯基的想法”的承诺，容易把当代归纳当成作者原话。
- 底部空的“全库卡片匹配”距顶部清单很远；搜索层级与状态需要重组。用户也应看得出这是即时筛选还是提交搜索。

### 10-search

- **顶部 “Server-side Search · FastAPI / Cloudflare Workers + SQLite FTS5” 与大号 static-client 抢占注意力**。实现信息放进技术说明或可展开状态，公开入口改为“全库搜索”。这是界面层级意见，与后端降级是否为缺陷无关。
- 一排搜索、来源、主题、类型、每页数量，下一排随机卡和两种导出，控件都是近似胶囊样式。突出输入框与搜索动作，让筛选、导出各有次级位置。
- 空查询显示全库 1386 张可以接受，但“全部卡片”比“命中卡片”准确。输入查询后应展示关键词、真实总数和页码上下文。
- 中文摘要比 03／04 的原文长预览更适合扫读，但两类内容使用近似视觉层级，最好标明“中文转述”或“原文匹配片段”，保持跨页语义一致。
- **本地静态检索降级横幅不计为功能缺陷，也不拿它作为扣分理由。**

### 11-mobile-index

- **品牌占满大部分宽度，导航只露“首页”和下一项残片，三枚主题色按钮仍固定占位。** 手机导航不是“容器不溢出”就算完成；缩短品牌或将主题切换收进“更多”，为主要入口让位。
- 标题切成“从原著里长出的教育／智慧”，最后两个字孤悬，重心不稳。缩短标题，或在移动断点安排句意完整的换行。
- 搜索按钮折成全宽、文字靠左的胶囊，**像第二个输入框**。应明确它与输入框的关系，或使用更明确的实心主按钮。
- 统计区之后还有大块空白，“读内容”约七百像素后才开始，第一张入口卡更靠下。首屏应更早给出直接阅读动作。
- 四张大入口卡依次堆叠，之后还有长说明列表，首页接近 3900 像素高。问题在于选择入口所需的滚动距离过大；压缩卡内留白比压小正文更合适。

### 12-mobile-map

- **只露左侧部分矩阵不是裁切 bug**。页面不横滚、矩阵内部横滚可以保留；强行将 22 列塞进 390px 会让数字更难读。
- 真正缺少的是**明确横滑提示与当前位置说明**。读者应知道右侧还有哪些角度，横滑后仍能确定当前行代表哪个条目。
- 图下仍写“把鼠标移到格子上”，源码也只提供鼠标高亮。手机需要点击后显示完整主题名、方向、张数及“查看这些卡片”；必要信息不能只存在于 title 提示。
- 规模区每条拆成名称行与条形行，22 个条目之后才到矩阵，主要阅读动作埋得很深。手机默认单主题关系列表，完整图作为展开项，更有效。
- “图例：编辑主归属分布”拆成不自然的两行，两侧解释相互挤压，应独占一行简明说明。页底三张长解释卡增加滚动，却没增加可读内容入口。

## C. 如果只能改三件事：按收益排序

### 1. 修复“原文”这一数据与展示契约

先处理已发现的 13 张“转述概括”卡及同类标注，分离原文与编辑摘要；列表不再无条件套引号。分类依据只在原文摘录中匹配，OCR 模糊匹配单独标为待复核；同时读全 38 张多段摘录卡，更新受影响的判读。

**收益：** 这是可信度底座。当前问题会让转述在展示、分类和核验三处循环成为自己的依据，比换配色更值得立即修。

**完成判据：** 读者能辨认一段话的身份，依据能定位到真实摘录；无法核验的卡有明确状态，验收不再把“有字”当成“有原文”。

### 2. 把“我想了解 X”做成真实可走的阅读路径

先以劳动教育为样例：A11 首屏直达主要论述、交叉参见、相关教学案例和故事，并提供带主题词的全库搜索出口。问题检索纠正整句匹配、仅零结果才查全文、30 条静默截断这三个行为；路径脚本核对页面集合与实际链接，不再先用关键词替网页删卡。

**收益：** 直接兑现最初的原型问题。保留主归属与参见即可，不需要全面推翻分类；先让读者不用理解后台术语也能抵达材料。

**完成判据：** 对劳动教育等四个问题记录“从哪进、几步到、看到什么、漏了什么”；对旧新差集做相关性复核，报告真正遗漏，而非只比较总数。教学案例不能因被标成 case 就退出主题阅读路线。

### 3. 让思想地图支持“选一个主题，沿关系读下去”

保留矩阵作为详细视图，增加默认的单主题关系视图：完整中文名称展示入向／出向联系；点一条关系，列出对应卡片。手机优先显示此视图，完整矩阵仍允许局部横滚，并提供显式提示和点击说明。

**收益：** 同时解决 07／12 的读图门槛、交互断点和“真正地图”的核心诉求。提供位置感与可探索性，无需用全量连线填满屏幕。

**完成判据：** 不记 A 编号、不依赖悬停，也能完成“劳动与哪些主题相连 → 为什么相连 → 读对应原文”的流程。

以上三项都可在现有静态 HTML、共享 CSS 和普通 JavaScript 中完成，框架、构建工具和更复杂的后端不在本轮必改清单内。其余空框、空区块、重复统计、移动导航和按钮层级按 B 节修正即可，不应让视觉微调挤掉前三项。
